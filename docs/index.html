AccessPath: the original backend

This is the first version of AccessPath, built with FastAPI and Postgres. It's posted here so the frontend team can see the API shapes, the review workflow, and the old UI prototype. The new Django backend replaces it. Use this for ideas, not as the contract.

Clickable UI prototype →Dashboard, review queue, upload, courses, activity. It runs on mock data, so no backend is needed. API reference →All 18 endpoints with request and response schemas (Swagger, read-only). openapi.json →The raw spec. Feed it to a codegen tool or a mock server.

Upload PDF / HTML / URL→ Split into elements→ AI drafts accessible version→ TA / prof approve or reject→ Export accessible course

Ideas worth carrying into the new frontend

  • Review queue as the home screen. Most TA time goes there. Show confidence, element type and flagged status at a glance.
  • Side-by-side review. Put the original element (image crop or snippet) next to the AI's draft, with approve/reject/edit right there (see NodeDetailPanel.jsx).
  • Version timeline. Since versions are immutable, show “AI generated → TA edited → Prof approved” as a history list.
  • Confidence badges. Sort or filter by AI confidence so low-confidence items get human eyes first.
  • Per-lecture progress bars. Approved / total / flagged per artifact on the dashboard.
  • Optimistic UI. The prototype updates the screen right away and falls back to mock data if the API fails. That's handy while the backend is still being built.
The API spec was generated from the original FastAPI code. The prototype's api.js points at localhost:8000, and when that isn't reachable the screens fall back to the sample data in AppData.jsx.
